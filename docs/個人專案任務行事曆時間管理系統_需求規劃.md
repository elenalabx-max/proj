# 個人使用的專案＋任務＋行事曆＋時間管理系統 — 需求規劃書

你現在要協助我建立一套「個人使用的專案＋任務＋行事曆＋時間管理系統」。

這不是多人團隊協作系統，不需要做成 Monday.com 那麼複雜。
目前主要使用者只有我自己，但系統仍必須具備帳號登入、雲端資料庫、不同裝置同步能力。

請先完整理解以下需求，再進行架構規劃與開發。

## 一、產品核心定位

這是一套結合：

1. 專案管理
2. 任務管理
3. Todo
4. Reminder
5. Calendar
6. 四象限時間管理
7. 交辦追蹤
8. 收集箱
9. 遺忘箱
10. 實際工時紀錄
11. 專案工時統計

的個人工作管理系統。

核心理念是：

「未完成，不代表現在需要出現在我眼前。」

事情即使尚未完成，也可能處於：
- 收集箱
- 今天
- 未來排程
- 專案
- 待他人
- 待我確認
- 遺忘箱

只有「現在真的需要我處理」的事情，才應該出現在主要 Today 畫面。

## 二、建議技術架構

希望採用：

Frontend：
- Next.js
- TypeScript
- Tailwind CSS

Backend / Database / Auth：
- Supabase
- PostgreSQL
- Supabase Auth
- Supabase Realtime

其他可使用：
- date-fns
- dnd-kit
- rrule 或其他成熟 recurrence library

必要條件：

1. 不可以將主要資料只存在 localStorage。
2. 所有主要資料必須寫入雲端資料庫。
3. 同一帳號登入不同裝置時，要看到相同資料。
4. 電腦新增或修改資料後，手機應同步看到。
5. 手機修改後，電腦也應同步。
6. 所有資料必須和 user_id 綁定。
7. 使用 Supabase Row Level Security 確保使用者只能看到自己的資料。

登入方式 V1：
- Email + Password
- Google Login

## 四、Area：個人 / 工作

系統最上層分成：

1. Personal 個人
2. Work 工作

所有 Task 可以歸類到其中一個 Area。

左側篩選可以：

```
☑ 個人
☑ 工作
```

工作底下還可以勾選 Project：

```
☑ 工作
   ☑ 台北PBC
   ☑ 學刊
   ☐ 高公局
   ☐ 其他專案
```

可以同時勾多個 Project。

例如：

勾選：
☑ 台北PBC
☑ 學刊
☑ 個人

Calendar 就同時顯示以上內容。

Project 是 Area 內的篩選條件，不應因為勾選多個 Project 就產生很多 Calendar 欄位。

## 五、顏色系統

這是必要功能。

### 【Personal】

個人 Area 可以設定自己的「預設顏色」。

例如：

Personal Default Color = 柔紫色

所有沒有另外設定顏色的個人 Task / Todo，在 Calendar 上預設使用這個顏色。

使用者可以到：

設定 → 顏色 → Personal 預設顏色

自由修改。

### 【Work】

Work 不使用一個統一顏色。

每一個 Work Project 都可以設定自己的預設顏色。

例如：

- 台北PBC = 藍色
- 學刊 = 綠色
- 高公局PBC = 橘色
- 系友會 = 紫色

Project 建立或編輯時要有：

Project Color

欄位。

此 Project 下的 Task 預設繼承 Project Color。

例如：

Project：台北PBC
Color：#4A90E2

底下：
- 半年分析報告
- 年度總結報告
- 委員意見
- 會議

Calendar Block 都使用台北PBC顏色。

V1 不需要強迫每一個 Task 都自己選色。

規則：

- Personal Task → 繼承 Personal Default Color
- Work Task → 繼承 Project Color
- 如果 Work Task 沒有 Project → 使用 Work 的 fallback 預設色。

未來可以擴充 Task Color Override，但 V1 可以先不做。

色彩選擇介面：
- 提供數個預設色票
- 同時允許 custom color picker

所有顏色必須支援：
- Light Mode
- Dark Mode
- 文字對比可讀性

- 博士

- 有 Project
- 沒有 Project
- 有日期
- 沒日期

- 進入四象限
- 有截止日期
- 交辦別人
- 設 Follow-up
- 設 Reminder
- 記錄實際工時
- 有 Subtask
- 設定重複

## 八、Task Status

不要只做：未完成 / 完成

要有：

1. inbox
2. todo
3. in_progress
4. waiting
5. review
6. completed
7. forgotten

中文顯示：

- 收集箱
- 待處理
- 進行中
- 待他人
- 待我確認
- 完成
- 遺忘

其中：

waiting：我已經交辦別人，目前不是我要執行。

review：對方完成，或到了 Follow-up 時間，需要我確認。

completed：我確認事情真正結案。

## 九、Subtask

Subtask 是 Task 底下的小步驟。

例如：

Task：完成年度成果報告

Subtask：
- □ 更新表1-1
- □ 更新表1-2
- □ 修改1.1
- □ 修改1.2
- □ 整理委員意見
- □ PDF確認

Subtask：
- 必須屬於 Task
- 可以勾完成
- 可以記 Time Log
- 預設不單獨出現在 Calendar

如果某個 Subtask 需要：
- 獨立日期
- 獨立排程
- 獨立 Deadline
- 獨立交辦

應提供：「轉成 Task」功能。

## 十、Todo

Todo 是很小、很單純的待辦。

例如：
- 買洗衣精
- 換圖書館密碼
- 問學長照片
- 買收據夾

Todo 不要求：
- Project
- 開始時間
- 結束時間
- 工時

Todo 可以只有：

```
title
date
completed
```

也可以沒有日期而存在 Inbox。

Todo 可以：
- 加 Reminder
- 排入 Today
- 排入某天
- 放入 Forgotten
- 轉成 Task

Todo 的 Time Log 為選用功能，不強迫填。

## 十一、Reminder

Reminder 不是 Task。

Reminder 的目的只有：「在某一個時間提醒我。」

Reminder 可以：
1. 獨立存在
2. 掛在 Project
3. 掛在 Task
4. 掛在 Todo

例如：

Task：完成半年分析報告

Reminder：9/3 09:00 提醒我處理

Reminder 至少包含：

```
id
user_id

remind_at

linked_type
linked_id

title
note

completed_at
```

## 十二、收集箱 Inbox

Inbox 是：「想到事情，但是還沒決定怎麼安排。」

使用者快速新增事項時，可以只輸入：標題

不用強迫選：Project / 日期 / 時間 / 重要性

建立後先進 Inbox。

Inbox 每筆事情應有快速操作：

```
[今天] [明天] [選日期] [加入專案] [遺忘]
```

支援批次：

```
☑ A
☑ B
☑ C

→ 移入 Project
→ 排到某一天
→ 放入 Forgotten
```

## 十三、遺忘箱 Forgotten

Forgotten 是：「這件事還沒有完成，但我現在完全不想看到。」

與 Completed 完全不同。

Forgotten 支援兩種：
1. 無限期遺忘
2. 遺忘到某一天

例如：

研究 AI 工具
Forgot Until：2026/10/01

在 10/1 前：
- 不出現在 Today
- 不出現在 Calendar
- 不出現在普通 Todo

10/1 到期後：自動回到 Inbox，並提示：「之前擱置的事情，要重新安排嗎？」

Forgotten 不需要一直顯示紅色未完成數量。

## 十四、交辦 / Waiting

即使系統目前只有我自己登入，我仍然會把工作交辦給別人。

例如：請奕賢修改報告。

對方不需要擁有系統帳號。

我要可以自己建立 Person：
- 老師
- 奕賢
- 廠商
- 監造
- 機關承辦

Person Table：

```
id
user_id
name
note
```

Task 可以指定：Assignee

例如：

Task：修改期末報告
Assignee：奕賢

交辦後：status = waiting

這件事情不應該繼續占據我的 Today Todo。

## 十五、Deadline 與 Follow-up 必須分開

非常重要：

「對方應該完成的時間」和「我要確認的時間」不是同一件事。

例如：

請 A 9/5 前給資料。

delegate_deadline：9/5 17:00

但：

follow_up_at：9/4 15:00

9/4 15:00：系統提醒我：「A 的『PBC統計資料』明天到期，要不要確認進度？」

如果對方還沒完成：我可以按：延後追蹤

例如：明天 10:00 再確認。Task 回到 waiting。

到了新的 Follow-up：再出現在 Review / 待確認。

## 十六、Today

首頁預設應為：Today，而不是 Project List。

Today 主要回答：「我今天到底要做什麼？」

Today 可以看到：
1. 今天排程
2. 今天 Todo
3. 今天需要 Follow-up
4. 今天 Reminder

但 Waiting 中尚未到 Follow-up 時間的事情：不要一直占 Today。

## 十七、Calendar

Calendar 必須有：Month / Week / Day 三種檢視。

## 十八、Day View

Day View 有兩種模式：
1. Timeline
2. Eisenhower Matrix 四象限

上方切換：

```
[時間軸] [四象限]
```

## 十九、Day Timeline 特殊版型

這是核心 UI。

Day Timeline 必須做成：

左側：Work
右側：Personal

兩邊共用同一條時間軸。

例如：

```
時間       工作                    個人

整天     PBC發文                  繳信用卡

09:00    修改報告

10:00                            博士論文
11:00

13:00    委員邀請信

14:00    PBC會議

15:00                            運動
```

Work 固定左側。
Personal 固定右側。

這叫：Two-lane Timeline

Project 不增加額外欄位。

例如勾選：

Work：☑ 台北PBC ☑ 學刊
Personal：☑ 博士

仍然只有：Work | Personal 兩欄。

Work 欄內同時顯示：台北PBC / 學刊

不同 Project 使用各自 Project Color。

Personal Block 使用 Personal Default Color。

## 二十、Area 顯示切換

使用者可以：☑ Work ☑ Personal

如果兩個都選：50% / 50%（Work | Personal）

如果只選 Work：Work 自動使用 100% 寬度。

如果只選 Personal：Personal 自動使用 100% 寬度。

## 二十一、Calendar Block 操作

Task Block 必須支援：
1. Drag & Drop
2. 上下移動改時間
3. 跨日期移動
4. Resize

例如：

14:00–15:00

拉長：

14:00–17:00

scheduled_end 自動更新。

Calendar 上拖曳應更新資料庫。

如果不同裝置開著：透過 Realtime 同步更新。

## 二十二、全天任務

Task 可以選：All Day

All Day Task：不佔小時時間格。

固定顯示在 Day View 上方：全天

Work / Personal 仍然左右分區。

## 二十三、Due Date 與 Scheduled Time 必須分開

非常重要。

例如：

年度報告截止：9/7

但我要：9/3 14:00–17:00 進行修改。

資料應分成：

```
due_date = 9/7

scheduled_date = 9/3
scheduled_start = 14:00
scheduled_end = 17:00
```

不要只設計一個 date 欄位。

## 二十四、四象限

Task 有兩個 Boolean：important / urgent

產生四象限：

- 重要＋緊急
- 重要＋不緊急
- 不重要＋緊急
- 不重要＋不緊急

四象限模式不要再切 Work / Personal。否則會變八格。

每張 Task Card 顯示：

```
Task Name
Area
Project
```

例如：

```
修改半年報
工作 · 台北PBC
```

或：

```
博士論文修改
個人 · 博士
```

Task 可以拖曳到另一個象限。

例如：重要不緊急 → 拖到重要且緊急，系統自動修改 urgent。

## 二十五、重複任務

Task 和 Todo 可以設定 Recurrence。

例如：每天 / 每週 / 每月 / 每年 / 自訂

設定方式可以包含：

```
每天

每週：星期一 星期三 星期五

每月：每月5日

每年：每年9月1日
```

必要規則：

Recurring Task 每一次出現必須是獨立 Instance。

例如：每月5日整理帳務。

9/5 10/5 11/5 12/5 是四個獨立 instance。

9/5 勾完成：只影響 9/5。

絕對不可以把 10/5 11/5 12/5 一起改成完成。

同樣地：修改 9/5 這次 Task 的內容，預設只修改此次。

系統可以詢問：

```
只修改此次
修改此次及未來
修改全部
```

但「完成」永遠只完成單次 Instance。

## 二十六、工時管理

這是核心功能。

必須明確分開：Estimated Time / Scheduled Time / Actual Time

例如：

```
預計：2 hours
排程：14:00–16:00
實際：3 hours 20 minutes
```

三者不能混用。

## 二十七、Time Log

實際工時不能只存在 Task 上的一個數字。

必須建立：Time Log

每次工作產生一筆。

例如：

Task：半年分析報告

Time Logs：

```
9/1  14:10–16:30  2h20m
9/2  09:15–11:00  1h45m
9/2  14:00–16:30  2h30m
```

Task Actual Time：自動 SUM(Time Logs)

Time Log 建議：

```
id
user_id

task_id
subtask_id
todo_id

log_date

started_at
ended_at

duration_minutes

note

source

created_at
updated_at
```

source：timer / manual

## 二十八、計時器

Task 詳細頁提供：▶ 開始工作

按下後：開始 Timer。

例如：

```
00:00:00
00:15:32
01:25:18
```

按：■ 停止

自動建立 Time Log。

同一使用者同一時間預設只能有一個 Active Timer。

如果另外一個 Task 按開始：應先詢問：「目前正在計時『XXX』，是否停止並切換？」

## 二十九、手動補登工時

使用者一定要能補登。

例如：

新增工時，日期：9/1

方式一：

```
13:30 ～ 15:10
```

系統算：1h40m

方式二：直接填：1 小時 40 分

Time Log 都要可以：新增 / 編輯 / 刪除

## 三十、Subtask 工時

Subtask 可以建立自己的 Time Log。

例如：

Task：年度總結報告

Subtask：
```
更新表格 2h10m
修改1.1  1h40m
成效分析 4h15m
```

Task Actual Time：自動加總所有相關 Time Log。

注意：不能重複計算。

如果 Time Log 掛在 Subtask：Project 統計時只 SUM Time Log。不要再加一次 Task Total。

## 三十一、Project 工時統計

每個 Project 要有 Statistics。

例如：

台北PBC

```
總預計：25h
總實際：32h35m
差異：+7h35m
差異比例：+30%
```

並列出：

```
半年分析報告  預計 6h   實際 8h35m
年度總結報告  預計 10h  實際 13h20m
委員意見      預計 3h   實際 4h10m
```

可以顯示：
1. Total Actual Time
2. Total Estimated Time
3. Estimated vs Actual
4. 各 Task 工時占比
5. 每週投入工時
6. 每月投入工時

V1 不需要做非常複雜的企業 Dashboard。保持簡潔。

## 三十二、Week View

Week View 類似一般 Calendar。

顯示：Monday Tuesday Wednesday ...

Task Block 使用自己的顏色。

Work Project：使用 Project Color。

## 三十三、Month View

## 四十七、UI 設計方向

整體：乾淨 / 簡潔 / 不要企業 ERP 感 / 不要塞滿表格

視覺參考：

- Monday.com 的：Project Color / Task Block / 拖曳
- Google Calendar 的：時間安排
- 一般 Todo App 的：Inbox / Forgotten
- Eisenhower Matrix 的：四象限

但不要直接複製任何產品。

主要使用體驗應該是：

```
今天       → 我要做什麼
Calendar   → 我的時間怎麼安排
Projects   → 這個專案還有哪些事
Waiting    → 別人還欠我什麼
Statistics → 我到底花多少時間
```

## 四十八、重要 UX 原則

1. 不要因為 Task 未完成，就永遠顯示在 Today。
2. Waiting 不應污染我的 Todo。
3. Forgotten 不應污染我的未完成數量。
4. Follow-up 到時間才重新引起注意。
5. Calendar 的排程時間不是實際工時。
6. Actual Time 必須來自 Time Log。
7. Recurring Task 完成本次，不得影響未來 Instance。
8. Personal / Work 在 Day Timeline 必須左右分欄。
9. Project Color 必須清楚反映在 Work Task。
10. 新增 Task 要快，不能每次強迫填十幾個欄位。
